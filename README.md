# そねき — FX損益管理PWA

iPhone Safariを主対象とした、端末内保存のFX取引ノートです。HTML/CSS/Vanilla JavaScriptのみで動作し、アプリのビルド・外部ライブラリ・CDN・外部API・ログインは不要です。

表示はダークモードです。カレンダー画面は利益を緑、損失を赤、ゼロを通常色で表示します。今回指定のない約定履歴・分析画面は従来の利益＝赤、損失＝緑の配色を維持します。

## 利用方法

公開先: https://mimassa.github.io/soneki/

1. Safariで開き、初回はオンラインで読み込みます。
2. 共有メニュー →「ホーム画面に追加」でインストールできます。
3. 「約定履歴」→「＋ 新規約定」で買い／売り、Lot、価格、日本時間の日時を登録します。
4. 親カードを開き「決済を追加」。部分決済は何件でも登録でき、未決済数量を超える入力は拒否します。
5. pips・建玉損益・スワップはFX会社の確定値を手入力します。Lotや価格差から円損益は計算しません。決済損益だけを建玉損益＋スワップで自動計算します。
6. カレンダーは月〜金の5列で、決済日時から算出したFX取引日基準です。日付→決済を選ぶと履歴の該当カードに移動し、強調表示します。戻ると月・通貨ペア・選択日を維持します。
7. 損益分析は月／年／全期間・通貨ペアで絞り込めます。通常集計の勝率の分母は、選択したFX取引日期間に含まれるゼロ損益を含む決済件数です。休場時間の例外決済は別枠に表示します。pipsは単純合算。平均損失は負数です。累積グラフは選択期間の開始から累積します。

## FX取引日と休場時間（1.1.0）

`isTradingTime(executedAt)`で取引可能時間、`getTradingDate(executedAt)`で取引日を判定します。取引可能時間外では取引日は`null`になり、別の営業日へ自動的に振り替えません。

| 日本時間 | 米国標準時間 | 米国夏時間 |
| --- | --- | --- |
| 月曜日の開始 | 07:15 | 07:15 |
| 火〜金曜日の開始 | 07:10 | 06:10 |
| 翌朝の終了 | 06:50:00.999まで | 05:50:00.999まで |

火〜土の早朝は前日の取引日です。日曜日、月曜日の開始前、各日の終了から開始までの間、土曜日の終了後は休場扱いです。例えば、2026年12月1日03:00の決済は11月30日、2027年1月1日03:00の決済は2026年12月31日に計上します。土曜早朝の決済も金曜日のセルに入ります。

米国夏時間は3月第2日曜日16:00 JSTから11月第1日曜日15:00 JST直前までです。毎年の曜日を計算し、端末のタイムゾーンに依存しません。米国東部時間の現行ルールを全対象年へ適用します。祝日・業者独自の臨時休場は判定しません。

カレンダーの日別・月間サマリ、分析の月／年／全期間、日別・月別・累積・通貨ペア別グラフは共通の取引日判定を使います。カレンダーと月間サマリは同じ通貨ペア条件・取引月です。明細と約定履歴の日時は実際の約定日時です。

### 休場時間の例外

- 新規・決済の入力中に警告し、保存時の確認で「OK」を選ぶと登録できます。キャンセルするとフォームと既存データを維持します。
- JSON復元でも、通常の取引時間外の新規約定・決済の件数を確認メッセージに表示します。
- カレンダー・分析画面の「休場時間の決済（全期間）」に例外の件数、損益合計、明細を表示します。明細から元の親子カードに移動できます。
- 例外一覧は**通貨ペアだけを絞り込み、月・分析期間には関係なく全期間を表示**します。通常のサマリ・グラフには混ぜません。
- 約定履歴の親カード確定損益、JSON、CSVは例外を含む全記録を保持します。このため履歴の総額と通常の分析総額の差は、例外損益に相当します。

取引日は表示時に算出する派生情報です。保存済み約定日時は変更せず、IndexedDBのバージョン・ストア・スキーマを変更／移行／初期化しません。既存のJSON（schemaVersion 1）と4種類のフォント設定を引き続き読み込めます。

## アプリ全体のフォント

「設定」→「アプリのフォント」で40種類の候補から選べます。既存の標準・サンセリフ・等幅・セリフを維持し、ヒラギノ角ゴシック／サンセリフ／明朝／丸ゴシック、Avenir、Baskerville、Didot、Futura、Palatinoなどを追加しました。選択メニューと、スクロール可能な「フォント名とサンプル」の一覧を用意しています。

選択した書体は日本語・数字を含む全画面、入力フォーム、ボタン、アプリ内ダイアログ、SVGグラフの文字へ即時反映します。設定は従来の`settings.numberFont`キーでIndexedDB・JSONバックアップに保存され、再起動後も維持します。旧バックアップに設定がない場合は標準を使います。

**候補は搭載・利用可能を保証する一覧ではありません。** Safariで書体を完全には列挙・検証できないため、アプリが候補を定義しCSSで指定します。利用できない書体や日本語に未対応の字形には日本語の代替フォントを指定しています。外部CDN・フォントファイル・ネットワーク読込はありません。フォントは端末・OSにより見た目が異なります。ブラウザ標準の確認ポップアップやファイル選択UIはOS側のフォントで表示され、アプリから変更できません。

## データと精度

IndexedDB `soneki-fx` の `Positions`・`Settlements`・`Settings` に保存します。取引・設定は外部に送信しません。GitHub Pagesには静的ソースだけを配置します。

**IndexedDBは端末内保存です。端末故障、Safariのサイトデータ削除、ブラウザによる保存領域の整理などで記録を失う可能性があります。定期的にJSONを別の場所へバックアップしてください。** 別端末・別ブラウザ・別オリジンとは同期しません。プライベートブラウズでの継続利用は避けてください。同時編集による上書きを避けるため、入力は1つのタブで行ってください。

数値は整数14桁・小数8桁までの10進文字列で保存し、BigIntの固定小数演算を使います。数量・円損益・pips合算に二進浮動小数誤差はありません。平均値は小数8桁で切り捨て、グラフ座標と勝率のみNumberで計算します。日時は `YYYY-MM-DDTHH:mm:ss+09:00` の日本時間を使い、末尾に1〜3桁の小数秒がある形式（例：`06:50:00.999+09:00`）も受け付けます。保存済みの小数秒は編集・バックアップ時にも保持します。端末のタイムゾーン設定に依存しません。決済日時は新規約定日時以降に限定します。

## バックアップと復元

「設定」→「JSONエクスポート」で `fx-backup-YYYYMMDD-HHMMSS.json` を保存します。iPhoneではダウンロード先や「ファイル」アプリ内の保存を確認してください。実際のファイル保存完了は検出できないため、「最終エクスポート実行日時」と「エクスポート後の変更なし／未保存の変更あり」を表示します。エクスポート履歴の更新だけではデータ変更扱いにしません。

JSONは `schemaVersion: 1`、`exportedAt`、`applicationVersion`、`positions`、`settlements`、`settings` を含みます。インポートは最大20MB。形式・日時・数値・ID重複・親子参照・数量整合性を検証し、件数と全置換の確認後に、3ストアを1つのIndexedDBトランザクションで置き換えます。失敗時は既存データを維持します。復元は変更として記録されます。

CSVはUTF-8 BOM付きで全決済を出力します。完全復元にはJSONを使ってください。実データやバックアップをGitに追加しないでください。

## GitHub Pages公開

この変更のPull Requestを`main`にマージしてください。`main`に直接Pushする必要はありません。

リポジトリの **Settings → Pages → Build and deployment** で以下を設定します（管理権限が必要です）。

- Source: **Deploy from a branch**
- Branch: **main**
- Folder: **/(root)**

この設定後は`main`へのマージでGitHub Pagesが自動更新されます。`index.html`と`.nojekyll`はルートにあり、全アセット・開始URL・SW登録は相対パスです。公開先ではService Workerのスコープは`/soneki/`です。GitHub Pagesの管理設定はソースファイルだけでは変更できません。

## オフライン・更新

Service WorkerはHTML・Manifest・アイコンを同じバージョンのキャッシュに保存します。初回オンライン読み込み完了後はオフラインで入力・閲覧・バックアップできます。更新版のインストール後に通知が出ます。入力フォームを閉じて「更新する」を選び、確認すると新しいWorkerを有効化して再読み込みします。自動リロードはしません。古いアプリキャッシュだけを整理し、IndexedDBには触れません。

リリースごとに`index.html`の`VERSION`と`sw.js`の`CACHE`を更新してください。開いたままの場合は「設定」→「アプリの更新を確認」で確認できます。

## 開発とテスト

アプリの実行や公開にNode.js・ビルドは不要です。ローカル確認は親ディレクトリで `python3 -m http.server 8000` を実行し、`http://localhost:8000/soneki/` を開きます。Service WorkerはHTTPSまたはlocalhostで動作します。`file://`で直接開く方法は非対応です。

テストコードだけはNode.jsを使用します。

```sh
node tests/core.cjs
TZ=UTC node tests/trading.cjs
TZ=America/Los_Angeles node tests/trading.cjs
TZ=Asia/Tokyo node tests/trading.cjs
# PlaywrightとChromiumがあるテスト環境で実行
BASE_URL=http://127.0.0.1:8000/soneki/ CHROMIUM_PATH=/usr/bin/chromium node tests/browser.cjs
node tests/update.cjs
node tests/trading-browser.cjs
```

`core.cjs`: 正確な小数計算、部分決済の18,000円集計、数量超過・親数量縮小の拒否、売り、月跨ぎ、勝率ゼロ分母、pips、JSON往復、ID重複、孤立決済、不正日時、数値、必須データおよび数字フォント設定の互換性など18項目。

`browser.cjs`: 新規／部分決済、超過拒否、編集・削除、カレンダー往復・絞り込み、分析、JSONダウンロード・復元、不正JSON後のデータ維持、バックアップ状態、リロード永続化、オフライン登録、売りの買い戻し、320〜1280pxの横溢れを検証します。テスト用データは一時ブラウザプロファイル内だけに作成します。

`update.cjs`: 一時ローカルサーバーで新しいService Workerを配信し、更新通知、未保存フォームの保持、明示的な更新、古いキャッシュの削除、IndexedDB保持を確認します。

`trading.cjs`: 45項目。指示書の日時表、終了秒の.999、直後の休場、月曜特別開始、夏時間切替（2026〜2028）、月跨ぎ・年跨ぎ、2年分の毎時サンプル、3年分の5列日付配置、小数秒と旧バックアップ・フォントの互換性を確認します。UTC／America/Los_Angeles／Asia/Tokyoの3環境で通過しています。

`trading-browser.cjs`: 5列と損益色、土曜早朝・月／年跨ぎの合計、例外明細と履歴往復、通貨ペア絞り込み、休場警告のキャンセル／承認、小数秒を持つ編集とJSON復元、40フォント候補の反映・保存・日本語フォールバック、SVG文字と320pxの大きな金額の折返しを検証します。

18件のコア検証、45件の取引日検証（3タイムゾーン）、Chromiumの既存／新規操作テスト、更新テストは開発環境で通過しています。

### iPhone実機で確認する項目

- Safariからホーム画面追加、アイコン、standalone起動とSafe Area。
- 日本時間の日時ピッカー（小数秒を含む）と小数・負数キーボード入力。
- 各フォント候補の実際の字形、日本語フォールバック、5列の日付・大きな損益・長い文字列の表示。
- 休場警告、例外明細とカレンダーの往復、夏時間境界の実機表示。
- JSONの「ファイル」保存、ファイル選択での復元、CSVのExcel表示。
- 機内モードでの再起動・登録・閲覧。
- 次回リリースでの更新通知、入力中の更新抑止、更新後のIndexedDB維持。
- 実機の保存容量不足時のエラー表示とバックアップ復元。

Chromiumでの自動検証はiPhone Safari実機検証の代替ではありません。
